# 🛡️ Безопасность и ограничения Pi Calculator

## 🚨 Проблема решена: Защита от переполнения

### ❌ Что было не так:
При вводе экстремально больших значений (например, `900000000000` знаков) происходило **переполнение арифметики** в строке:
```rust
let prec = ((digits as f64) * 3.3219280948873626).ceil() as u32 + 64;
```

### ✅ Что исправлено:

#### 1. **Разумные лимиты для каждого алгоритма**
```rust
// Проверки добавлены в каждый алгоритм:
if digits > 10_000_000 {  // Binary Splitting
    panic!("Слишком большое количество знаков! Максимум: 10,000,000 знаков.");
}
```

#### 2. **Предварительная проверка в main.rs**
- Глобальный лимит: **50,000,000 знаков**
- Проверка совместимости алгоритма с запрашиваемым количеством знаков
- Обработка паники с информативными сообщениями

#### 3. **Обновленный интерфейс**
Теперь пользователи видят лимиты прямо в меню:
```
1. Чудновский (наивный) - стандартная реализация (макс: 1M знаков)
2. Чудновский (Binary Splitting) - самый быстрый для больших чисел (макс: 10M знаков)
3. Формула Мачина - классический быстрый метод (макс: 5M знаков)
4. Алгоритм Борвейна - квадратичная сходимость (макс: 2M знаков)
```

## 📊 Установленные лимиты

| Алгоритм | Максимум знаков | Причина ограничения |
|----------|----------------|---------------------|
| **Чудновский (наивный)** | 1,000,000 | Квадратичная сложность, медленный для больших чисел |
| **Binary Splitting** | 10,000,000 | Лучшая масштабируемость, но ограничен памятью |
| **Формула Мачина** | 5,000,000 | Сходимость замедляется для очень больших чисел |
| **Алгоритм Борвейна** | 2,000,000 | Требует много памяти для промежуточных вычислений |

## 🛡️ Механизмы защиты

### 1. **Многоуровневая защита**
```rust
// Уровень 1: Ввод пользователя (main.rs)
Ok(n) if n > 50_000_000 => {
    println!("⚠️  Слишком большое значение! Максимум: 50,000,000 знаков.");
    1000  // fallback
}

// Уровень 2: Проверка совместимости алгоритма
if digits > max_digits_for_algorithm {
    println!("❌ Ошибка: Выбранный алгоритм не поддерживает {} знаков!", digits);
    return;
}

// Уровень 3: Защита в самом алгоритме
if digits > 10_000_000 {
    panic!("Слишком большое количество знаков!");
}
```

### 2. **Обработка паники**
```rust
let pi_str = match std::panic::catch_unwind(|| {
    pi::compute_pi(digits, algorithm)
}) {
    Ok(result) => result,
    Err(_) => {
        println!("❌ Произошла ошибка при вычислении!");
        return;
    }
};
```

## 💡 Рекомендации пользователям

### ✅ **Безопасные значения**:
- **< 1,000 знаков**: Любой алгоритм работает мгновенно
- **1,000 - 100,000**: Все алгоритмы показывают отличную производительность
- **100,000 - 1,000,000**: Рекомендуется Binary Splitting или Borwein
- **1,000,000 - 5,000,000**: Только Binary Splitting для оптимальной производительности

### ⚠️ **Предупреждения**:
- **> 5,000,000 знаков**: Требует значительного времени (минуты) и памяти (ГБ)
- **> 10,000,000 знаков**: Не поддерживается для защиты системы

## 🔧 Технические детали

### Почему эти лимиты?

1. **Память**: Каждый знак требует ~3.32 бита точности
   - 1M знаков ≈ 400KB точности
   - 10M знаков ≈ 4MB точности
   - 100M знаков ≈ 40MB точности

2. **Время**: Binary Splitting O(M(n) log n)
   - 1M знаков: ~1-10 секунд
   - 10M знаков: ~1-5 минут
   - 100M знаков: часы

3. **Стабильность**: Предотвращение:
   - Переполнения арифметики
   - Исчерпания памяти
   - Зависания системы
